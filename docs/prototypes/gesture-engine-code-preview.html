Gesture engine: who does what

A sketch of the five files that the ticket 005 decisions produce. Read the diagram first, then choose a scenario on the left and step through it. Each step highlights the lines that run, in whichever files they're in. The code is a sketch: it isn't compiled, and the action payloads are only illustrative.

Five files, each answering one question

Note.tsx
Which Gesture kind?
Picks the kind at press time: body → move, handle → resize. Also dispatches raise.
→
useGesture.ts
How do we talk to the DOM?
Filters presses, captures, attaches listeners, writes styles and data-attributes. Holds no decisions.
→
controller.ts
When does each thing happen?
The lifecycle, written once: dead zone, scroll compensation, release/cancel/Escape, cleanup.
→
kinds.ts
What does it show and save?
Pure: preview() returns a rect plus overTrash; commit() returns an action or null.
→
geometry.ts
What is the maths?
Pure: moveRect, resizeRect, clampToBoard, pointInRect, roundRect.

    What the sketch adds beyond the decisions so far
    
    
    Writing real-looking code surfaced three details. They're refinements, not reversals, and they're open for you to accept or reject:
    
    
      
      
    1. Kinds are generic over what they start from: GestureKind<From extends Rect>. Move and resize are GestureKind<Note>, so their commit can read note.id. start is generic, so passing a plain rect to moveKind is a type error.
      2. 
      
    2. Capture moves out of io and into start (it's a DOM step, done right after filtering). In io, a single listen(handlers) → detach replaces separate scroll and keydown subscriptions: every listener is attached in one call and detached in one call, so none can be forgotten (Q1's bug class).
      3. 
      
    3. Because listen attaches native listeners on the captured element itself, lostpointercapture still reaches the controller after the Note is removed. Round 3's Q5 gap therefore only affects React's onLostPointerCapture, which this design doesn't use. dispose() stays as a safety net for StrictMode and for browsers that skip the event.
